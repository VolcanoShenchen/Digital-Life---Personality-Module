# 静态资料、动态状态与连续气泡调整方案

状态：动态状态分离已在 0.3.0 实现并进入本地验证；消息分段方案仍未实施。

## 1. 已确认的问题

1. 当前 `build_persona()` 每轮将 `background.current_situation` 作为“当前生活处境”放入系统提示，且没有时间或过期机制。
2. 测试人设中的“最近在整理旧照片”是持续项目，却容易被理解为每时每刻的当前活动。相关文字不一定只存在于这个字段；迁移时需检查身份描述、示例等重复来源。
3. 同样可能混淆的字段包括 `profile.location`（常住地还是即时位置）、`personality.desires`（长期愿望还是待办）、`relationship.stage`（长期阶段还是当前态度）。
4. 本地 AstrBot 4.29.4 原生分段关闭，流式回复关闭。原生分段默认超过 150 字不拆；使用标点拆分和随机 1.5～3.5 秒间隔，不能直接代表自然气泡策略。
5. AstBot 原生消息生成/历史保存与发送流程分开。发送失败时原生分段会记录错误并继续余段，不能保证历史只包含成功送达的文字；这是需要明确处理的限制。

## 2. 信息分类原则

- 静态：角色资料或表达规则，由配置维护，不能被一句普通聊天随意覆盖。
- 缓慢变化：有变更依据时更新，保留确认时间或历史；不每轮生成。
- 动态：当前事实，需要来源、观察时间、有效期和作用域。过期后不再作为当前事实注入。
- 行为倾向与行为事实分开：`when_tired` 描述疲惫时如何回应，不表示现在疲惫。
- 参数是配置：回复长度、分段间隔、人格来源不属于角色心情，也不自动变化。

## 3. 现有字段分类对照

| 字段或字段组 | 类别 | 调整建议 |
| --- | --- | --- |
| `profile.name/nickname/gender_identity/pronouns/species/nationality/native_language` | 静态身份 | 继续保留于角色设定，明确修改才变更 |
| `profile.birth_date` | 静态事实 | 出生日期保留；不得只依赖模型计算年龄 |
| `profile.age/age_mode` | 混合 | 固定年龄保留；增长模式改为出生日期+参考时间计算；时间线模式需明确角色日期，缺少条件时不假装已计算 |
| `profile.timezone` | 稳定配置 | 用于状态时间计算，时区不是当前时间 |
| `profile.location` | 混合 | 拆为常住地与即时位置；旧值先迁移为常住地，不能默认为当前所在 |
| `profile.occupation/education/social_status` | 缓慢变化的资料 | 默认作为长期背景；实际工作变更需明确更新 |
| `background.identity/family/childhood/education_history/work_history` | 静态或长期资料 | 保留，区分既往经历与进行中的活动 |
| `background.important_events` | 历史事实 | 已发生事件可追加、纠正；不是今天再次发生 |
| `background.current_situation` | 混合，必须拆分 | 迁移为“近期生活背景/进行中的项目”；新增当前活动状态，旧文本不继续当即时活动 |
| `background.world_setting` | 静态世界规则 | 不随普通闲聊改变 |
| `background.known_facts/unknown_facts` | 长期资料 | 描述知识范围；学习新事实应有来源，不等于模型什么都知道 |
| `background.secrets` | 稳定背景+披露规则 | 内容本身静态，是否披露是条件策略；简单换成动态字段不会解决泄露问题 |
| `personality.core_traits/positive_traits/flaws/values/dislikes/fears/insecurities/pride/contradictions/self_image/view_of_others/legacy_summary` | 稳定倾向 | 保留；“害怕被丢下”不表示现在正在被冷落 |
| `personality.desires` | 长期动机为主 | 长期愿望保留，具体项目/待办拆为具有状态的目标；完成后不能永远重复进行中 |
| `personality.changeability/social_temperature` | 稳定策略 | 变化方式、慢热倾向；不是每轮重置性格 |
| `behavior.when_*` 全部 | 静态条件规则 | 保留为“若发生则如何回应”；不会自动证明情绪/行为已发生 |
| `relationship.target_session/target_bot_id` | 稳定作用域 | 不自动改变、不按昵称推断 |
| `relationship.role/stage/trust_level/intimacy_boundary` | 缓慢变化 | 人工配置作为基线；当前受伤/放松等即时态度另存，不因一句话改关系身份 |
| `relationship.duration` | 可计算资料 | 建议相识日期+参考时间；旧文字仍可作为描述，不假装自动增长 |
| `relationship.background/shared_history` | 已确认关系事实 | 历史只追加或纠正，不当作当天活动 |
| `relationship.shared_interests` | 长期偏好 | 可在有依据时更新，不每轮推断 |
| `relationship.addressing/addressing_for_character/sensitive_topics/conflict_style/repair_style` | 静态相处规则 | 保留；与当前称呼、话题选择和情绪分别处理 |
| `speech.*` 全部 | 稳定表达偏好 | 保留；当前情绪只适度调节，不覆盖核心说话方式 |
| `response.*` 全部 | 稳定回复策略 | 保留，服从当轮任务需要 |
| `roleplay.*` 全部 | 稳定描写偏好 | 保留；动作描写不自动成为现实行为记录 |
| `boundaries.*` 全部 | 稳定边界规则 | 不随关系或情绪自动放宽工具权限 |
| `examples` | 静态风格示范 | 不转为真实历史，不因示例“我刚到家”就记录现在在家 |
| `enabled/persona_source/persona_authority/allowed_*` | 插件配置 | 不混入角色动态状态 |
| 旧 `character.* / expression.*` | 兼容入口 | 按新分类迁移；保留备份，禁止静默丢弃内容 |

## 4. 建议新增的动态状态

| 状态 | 含义 | 建议有效期/更新方式 |
| --- | --- | --- |
| `current_activity` | 当前活动 | 短期，例如 30～60 分钟；明确切换或完成即失效 |
| `current_location` | 当前场景位置 | 与活动和移动事实关联，不能随机瞬移 |
| `mood` | 当前情绪 | 有互动依据、强度及衰减；不能单凭关键词认定 |
| `energy` | 当前精力 | 有时间或明确事件依据，首版可以人工填写 |
| `interaction_attitude` | 对本次互动的即时态度 | 按角色+机器人+目标私聊隔离 |
| `active_topic/open_topic` | 当前/未完话题 | 有最后互动时间，换话题或过期时弱化 |
| `ongoing_projects` | 近期进行中的项目 | active/completed/paused，有开始/更新时间；不能一直作为当前活动 |

所有状态共同具有：作用域、值、来源、更新时间、有效截止时间、状态。状态不由示例、引用或模型随口生成的回复自动确认。

角色自身活动可以是共享世界状态；针对用户的态度和话题必须私聊隔离。首个版本建议先限定到当前单角色单用户，其他窗口不自动继承；共享生活状态另行显式启用。

### 首次实现建议

- 先实现人工可管理、有有效期的当前活动/位置/情绪，以及近期项目。
- 只有可靠、明确的更新才能取代现有状态；自动识别与日程模拟后续单独加入。
- 不增加每轮二次模型调用，不随机编出“新活动”来制造变化。
- 过期无新状态时，不重复旧活动，不声称已完成某事；在角色语境下自然表达没有特定安排，或只依据本轮明确上下文回答。
- 新状态作为本轮临时上下文提供，不能写回稳定系统人格；需要使用宿主支持的临时内容标记，避免在历史中无限积累并再次变成过时事实。
- 诊断显示状态的来源和剩余有效期，UI 将“长期资料”和“当前状态”分开。

一个活动在有效期内仍可能被合理重复提及；到期本身只说明证据失效，不证明活动已经结束，也不要求回答每次都不同。

## 5. 气泡分段策略

用户需要的是独立的连续 QQ 消息，不是一个消息内的换行，也不是合并转发卡片。

例：

```text
气泡1：刚把手边的书收好。
气泡2：你今天下班挺晚。
气泡3：路上还堵吗？
```

### 默认建议

- 普通闲聊按自然段和完整句意拆成 2～3 个气泡，短回复允许只有一个。
- 小句合并、长段在句末拆，保留标点；避免一句“嗯”也单独发，避免每个逗号都拆。
- 建议最小约 15 字、目标约 40～100 字，最多 4 泡；超出后合并余段，不丢弃正文。
- 间隔建议 0.6～1.2 秒，可配置；不把固定长等待当作拟人。
- URL、小数、括号内容、Markdown 代码块、列表和表格尽量作为完整片段，技术回答优先保留结构。
- 图片、音频、引用及工具回执保持原消息链顺序；首轮只拆普通模型文本。
- 管理命令、错误提示等默认不分段。

这些是拟定参数，尚未修改实际宿主。

## 6. 接入选择及原生限制

已核对 AstrBot 4.29.4：

- ResultDecorateStage 将正文切成多个 Plain 组件。
- RespondStage 在开启原生分段时逐个 Plain 发出并等待间隔，QQ 可得到多条消息。
- 没开原生分段时，仅切成多个 Plain 仍可能出现在同一气泡；不能误以为改链就够了。
- 流式消息走独立 send_streaming 路径，不可在已发送流式后再补发整段。
- 历史与模型过程记录并不由最终发送结果严格驱动；原生分段发送失败会继续发送后续组件。

### 推荐实施阶段

1. **宿主原生分段验证**：在明确的测试配置范围启用原生分段，按空行/完整句和短间隔验证 QQ 连续气泡。核对长消息阈值和模型文字，避免默认 150 字跳过分段。
2. **插件可配置切分**：增加 delivery 页面和切分器，保护代码、链接、表格和多模态。发送仍复用宿主管线；保存插件配置不能悄悄改写 AstrBot 全局设置，需显示当前宿主模式及必要配套配置。
3. **高级发送编排**：若要求收到新消息立即打断、失败停止余段或严格按送达写历史，则必须设计队列、取消与历史契约，不能宣称原生设置已提供。当前版本先不承诺这些行为。

首轮以当前非流式模式验证；流式与气泡模式选择应在 UI 明确，之后再实现完整流式兼容。

## 7. 验收

### 状态

- 旧“整理照片”只作为近期项目存在，不再每轮固定声称正在做。
- 活动在有效期内连续，替换或过期后不再作为当前事实。
- 无新状态时不随机填新活动，不从示例和历史片段把旧事认成新事。
- 关系态度与话题不串会话。
- 重启、备份、过期和手动修改行为有明确验证。
- “生气时怎么说”的静态规则不等于“现在正在生气”。

### 分段

- 多段回复在 QQ 中出现多条独立消息，顺序正确，无重复整段。
- 单句不硬拆，长回复不因 150 字阈值自动退化为单气泡。
- 代码/URL/小数/表格保留，图片工具内容顺序正确。
- 无额外模型调用，无正文截断。
- 原生发送失败继续余段、历史先于确认等限制须在诊断和文档中明确；未实现高级编排时不能写成已经支持。

## 8. 下一步范围建议

先实施“长期背景与临时状态拆分 + 可过期活动管理 + 基础连续气泡”，继续保持角色主控和现有私聊作用域。自动生活模拟、自动状态推断、持久情绪成长和复杂分段队列分别安排后续模块。
