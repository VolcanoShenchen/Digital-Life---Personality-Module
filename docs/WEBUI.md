# 配置 WebUI

插件详情页提供 `settings` 视图，源码位于 `frontend/`，由 Vue 3 + Vite 构建到 `views/settings/`。页面通过 AstrBot Dashboard 登录态访问插件后端，不另开端口。

## 页面结构

| 区域 | 内容 |
| --- | --- |
| 基础作用域 | 启用状态、人格来源、私聊 UMO、机器人 QQ 号 |
| 基础资料 | 姓名、昵称、性别认同、年龄及年龄模式、职业、教育与所在地 |
| 经历与世界 | 身份背景、家庭、成长、工作、重要事件、秘密、世界规则、已知与未知 |
| 性格核心 | 核心特征、优点、缺点、价值观、偏好、恐惧、欲望、不安全感、矛盾 |
| 情境行为 | 开心、难过、生气、疲惫、尴尬、焦虑、无聊、困惑、被夸奖、被批评、分歧、道歉、拒绝、被冷落、换话题、缺少记忆 |
| 专属关系 | 关系角色、阶段、时长、称呼、共同经历、兴趣、信任、亲密边界、冲突与修复 |
| 说话方式 | 自称、称呼、词汇、避免词、句长、标点、幽默、关心、分歧、道歉、拒绝等 |
| 回复策略 | 长度、先回答、追问频率、建议策略、复述、未知处理、套话与心理分析控制 |
| 动作与场景 | 动作风格、格式、环境细节、内心独白、感官细节 |
| 边界保护 | 敏感话题、禁止行为、拒绝强度、隐私、现实、记忆、工具和角色完整性 |
| 对话示例 | 多行表达示范 |

“经历与世界”“性格核心”等字段较多，通过左侧分组导航切换，避免长页面一次性铺开。

## 身份控制模式

在“基础作用域”区域有两个相关选择：

- **人格来源**：插件管理完整人格，或沿用 AstrBot 人格。
- **身份控制模式**：叠加模式，或角色主控模式。

推荐选择“插件管理完整人格 + 角色主控模式”。主控模式会明确告诉模型：角色是对话的第一身份，AstrBot、插件和模型只是运行环境；通用“助手”身份不应覆盖角色。用户明确询问平台、模型或插件时仍可如实回答。

如果选择“沿用 AstrBot 人格”，身份主控模式会被校验拒绝，因为此时角色身份来源不在本插件。



- 保存前做完整类型、枚举、必填和文本预算校验。
- 关系字段非空时必须绑定允许的会话和机器人。
- 校验失败不会改变正在使用的配置，也不会写入配置文件。
- 保存成功后，新模型请求立即使用新配置，无需重启宿主。
- 配置页保存的是插件自己的设置文件，不会修改 AstrBot 原生人格。

## 旧字段兼容

旧版 `character.name`、`character.identity`、`character.personality`、`character.boundaries` 与 `expression.*` 仍可读取。加载时其内容会迁移到结构化区域，例如：

- `character.name` → `profile.name`
- `character.identity` → `background.identity`
- `character.personality` → `personality.legacy_summary`
- `character.boundaries` → `boundaries.roleplay`
- `expression.*` → `speech.*`、`response.*`、`roleplay.*`

迁移只发生在内存中的配置快照，不擅自改写 AstrBot 配置文件；可在页面中逐步把旧内容复制到对应新字段。

## 构建与同步

修改 `frontend/` 后执行：

```bash
pnpm run build
```

输出覆盖 `views/settings/`。在本地测试环境中运行 `Sync-Plugin.cmd` 同步，然后重载插件或刷新页面。若页面没有更新，确认宿主目录内没有旧的 `app.js`、`style.css` 或旧哈希资源残留。

## 安全边界

页面不显示聊天记录、模型密钥或 OneBot token；配置内容只在当前 Dashboard 已登录用户访问时通过插件 API 返回。插件不会把完整角色资料写进聊天、错误日志或诊断命令。
