# 0.5.0 模型日程与时间线

## 生成内容来自哪里

默认方式是 **模型生成**。插件通过AstrBot的 `Context.llm_generate()` 调用你已配置的聊天模型，不单独保存API密钥。

模型会收到：角色身份与背景、职业与常住地、性格和偏好、动机、条件行为、近期生活背景，以及今天的日期/时区、作息、工作日、地点、固定时段和生成要求。模型据此规划具体活动和合理场景，输出结构化日程。

生成请求不读取用户聊天、专属关系和角色秘密，不提供工具，不执行现实动作，不发送QQ消息。上一份同角色的自动计划可以作为避免重复的参考，但明确不是已发生的记忆。

已移除代码中硬编码早餐/工作/休闲等活动内容的生成器。日期、时间校验、存储和当前时段匹配仍由程序完成。生成失败不拿固定规则内容冒充模型结果。

## 模型与配置

日程模块默认关闭；开启并保存后，如果“每天自动生成”也已开启，后台开始生成今日内容。

| 设置 | 用途 |
| --- | --- |
| 生成方式 | 默认 `llm` 模型生成；`template` 仅用于用户明确填写固定模板 |
| 日程模型 | 选择AstrBot已配置的聊天模型；留空使用宿主默认聊天模型 |
| 模型生成要求 | 真正发送给模型的自然语言要求，例如安排兴趣活动、限制移动范围 |
| 模型超时 | 单次等待上限，默认90秒 |
| 重试冷却 | 失败后的重试间隔，默认900秒；不能反复点击跳过 |
| 日程时区 | 默认Asia/Shanghai，按该时区计算今日和跨日 |
| 作息、工作时间与工作日 | 规划约束，不再用来填固定活动标题 |
| 工作/居家地点 | 场景范围与默认地点约束 |
| 固定安排 / 模板 | 模型必须保留的固定时段；模板模式直接使用它 |
| 最多时间段 | 默认12，最大32；模型模式至少5段 |
| 允许手动修改 | 控制是否可以在时间线编辑今日安排 |

生成会使用所选模型的额度，按宿主提供商计费。成功后当天复用，不在每条聊天时重新生成。手动重新生成属于新的模型请求。

自动失败有冷却和每日尝试次数限制；达到上限后需要检查模型，再手动重试。配置保存返回成功只表示设置已经保存，生成是否成功请看时间线状态。

## 从设置到时间线

1. 进入“日程模块 → 生成设置”，选择模型，填写要求和作息，启用并保存全部配置。
2. 返回默认页“今日时间线”。生成中会显示进度并轮询结果，刷新/轮询不会创建新的模型请求。
3. 校验通过后自动展示当日日程，卡片注明模型来源和实际提供商；当前段高亮。
4. 每段可以单独展开编辑。草稿不会替换已保存卡片或作为当前事实使用；保存今日日程后才生效。
5. “重新生成”需确认替换已有安排。若处于冷却期，先等待页面显示的重试时间。

设置与时间线分开显示；窄屏也保留两页导航。离开日程页停止页面轮询，后台任务可以继续；再次进入可读取最新状态。手动草稿与revision保留，不能被轮询中的新结果静默覆盖。

## 输出与校验

模型必须返回当天日期、时区和时间段JSON。只接受分钟级HH:MM，结束可为24:00；模型日程须从00:00至24:00连续覆盖，不得重叠、倒序、超段数或更改固定时段。

字段是开始、结束、具体活动、地点、备注。输出有长度限制，只接受合法JSON或完整JSON代码块，不从任意散文拼凑计划；工具调用结果拒绝。

日期、时区、输出结构和固定安排由程序校验。性格贴合、活动合理性与场景过渡依靠规划提示和实际试用评价，不能仅凭JSON通过就承诺内容质量。

## 保存、并发与失败

日程与生成状态保存在AstrBot插件数据目录：

```text
data/plugin_data/astrbot_plugin_digital_life_personality/schedule/
  today_schedule.json
  generation_status.json
```

- 同日同设定成功结果复用，模型生成与模板生成记录不同来源。
- 旧 `persona` 模式按模型模式解析；旧固定规则自动计划不会继续作为模型结果。人工修改过的今日安排仍保留，明确确认才重生成。
- 生成状态在请求前持久化，插件重载不马上重复发起付费请求；取消、失败与冷却均有明确状态。
- 单个实例同一时刻只有一个生成任务；后台检查、手动按钮和聊天触发会合并。
- 模型等待期间配置、日期、角色或人工日程发生变化时，旧结果丢弃，不能覆盖新数据。
- 错误信息使用固定错误码，不将原始提供商异常、密钥、完整角色资料或模型输出写入公开错误。
- 失败保留已有有效的今日计划；没有今日计划时只显示失败/未生成，不伪造当前活动。普通人格聊天继续运行。
- 模块关闭不生成、不注入，后台模型任务随关闭/重载取消。跨日在后台检查时生成新一天。

## 回复怎样参考

只把当前匹配的活动和位置通过 `TextPart.mark_as_temp()` 提供给对话模型；不把整天计划塞入稳定人格，不持久保存该临时块。有效人工状态按字段优先，过期后恢复当前日程。

计划描述虚构角色生活，不代表现实行为已经执行或活动已经完成。回复仍走AstrBot普通链路。
