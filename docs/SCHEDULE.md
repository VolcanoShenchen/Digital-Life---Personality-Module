# 0.4.2 今日日程与时间线

## 生成方式

模块默认关闭。开启并保存后，按日程时区生成当天安排，后台每30秒检查日期，在无人聊天时也能跨日更新；重新启动会复用当天已保存日程。

两种生成方式：

- **角色与作息（默认）**：读取角色的职业、常住地，结合起床/睡眠、工作时间和工作日，自动生成覆盖00:00至24:00的日程内容，不需要手工填每个时段。正常默认作息细分为起床洗漱、早餐、上午事务、午餐休息、下午事务、晚餐、个人时间、睡前准备和跨午夜休息。工作活动使用角色职业，地点参考工作/居家设置。作息很紧或段数上限较小时保留更粗的连续安排；固定时段不截断。无职业且未指定工作地点时安排个人事务。
- **固定模板**：直接使用填写的时间段。可留空档，空档不声称角色在做特定活动。角色模式下模板也可以作为固定安排插入作息，例如午休或晚间读书。

生成不调用模型，不产生额外模型费用；同样的设定、日期会产生确定的安排，不为了每天不同而随机编造经历。这是第一版规则生成器，不是模型自由规划。`generation_rule` 在页面中作为日程补充说明，供对话模型参考；它不解析“九点到十一点做什么”等自由文本来更改时段，请用作息字段或固定模板精确设置。

## 配置

| 字段 | 含义 |
| --- | --- |
| `enabled` | 日程模块总开关；插件本身也必须启用 |
| `auto_generate` | 开启后首次保存/加载和跨日自动生成；关闭后需点生成按钮 |
| `generation_mode` | `persona` 或 `template` |
| `timezone` | IANA时区，默认Asia/Shanghai |
| `wake_time/sleep_time` | 起床、睡眠时间 |
| `work_start/work_end` | 工作开始、结束时间，首版须在清醒时间内 |
| `workdays` | ISO星期数字字符串，1为周一、7为周日 |
| `work_location/home_location` | 工作与居家地点，留空参考职业和常住地 |
| `template_lines` | 可选固定时段；模板模式必填 |
| `generation_rule` | 对话参考的补充说明，不作为自然语言计划编译器 |
| `allow_manual_override` | 是否允许编辑今日时间段 |
| `max_segments` | 时间段上限，默认12，最大32；角色模式至少5段 |

例：

```text
12:00-13:00 | 午餐与休息 | 图书馆休息区 | 不安排工作
19:00-20:00 | 阅读 | 家中 | 自由阅读
```

每行“开始-结束 | 活动 | 地点 | 备注”，后两项可以留空。只接受分钟级HH:MM，结束可为24:00；不接受单段跨夜、重叠或倒序。跨夜休息分成00:00-起床、睡觉-24:00两段。超出数量上限时报告错误，不能静默截掉余段。

## 回复时怎样使用

只把当前时间匹配的一段作为临时用户内容块提供给模型，包含日期、时区、时段、活动和位置。其他时段和整天日程不逐轮注入稳定人格。

日程表示虚构角色生活的当前安排，不是现实动作已经执行的证据。例如上午在图书馆、傍晚在家是对话场景，不会发起实际外出、定位或工具调用。应自然回答相关问题，不向用户机械播报时间表。

优先关系：

1. 有效人工状态已指定的活动或地点优先，日程不覆盖该字段。
2. 人工状态未指定的字段可由当前日程补充。
3. 人工状态过期后恢复当前日程，过期提示不会错误否认有效日程。
4. 日程空档、关闭或无有效数据时不补造活动；昨日计划不得冒充今日。

所有注入使用 `TextPart.mark_as_temp()`，不保存为持久历史。正常角色回复仍由AstrBot管理历史，不会因状态到期被删除。

日程属于当前单个角色，适用于插件允许的私聊与机器人；不会读取专属关系和用户聊天来生成共同活动。当前尚无多角色独立日历。

## WebUI操作

AstrBot → 插件详情 → `settings` → **日程模块**，默认进入 **今日时间线**：

1. 首次使用转到 **生成设置**，开启日程和自动生成，选择“根据角色与作息生成”，填写作息及地点并保存全部配置。
2. 保存后自动生成今日内容；返回 **今日时间线** 查看纵向按时段排列的活动和地点，生成设置不混在此页。
3. 当前时段高亮，其他项标记为“时段已过”或“稍后”，已过不代表活动已经完成。卡片使用已保存日程，不会把未保存草稿当成当前事实。
4. 点某个时段的“编辑”，只展开这一段的开始、结束、活动、地点和备注；收起保留草稿，取消恢复该段原值。点击“保存今日日程”持久化修改。
5. “重新读取”校对保存数据，“重新生成”在确认后替换今日安排；切换二级页或模块保留草稿，刷新页面丢弃未保存草稿。
6. 开启自动生成后每天自动更新，默认不需要逐段手填。若关闭自动生成，可点击生成按钮。

时间线不会自动开启被关闭的模块；关闭时显示前往生成设置的入口。当前安排只参考今日、模块已启用且读取成功的数据；昨日或异常数据不会显示为正在进行。

未保存的设置不会用于生成；读取失败禁止保存默认空配置。非法修改和网络失败保留草稿。页面使用revision检测其他窗口修改，冲突时返回409，需重新读取；不会静默覆盖别的窗口。

## 存储与错误

保存路径：AstrBot的 `data/plugin_data/astrbot_plugin_digital_life_personality/schedule/today_schedule.json`。

- 数据带日期、时区、角色签名、规则签名、版本和手动覆盖标记。
- 同一天人工编辑保留，不因后台检查、普通问话或改了作息参数自动丢失；明确重新生成才覆盖。换角色或时区后，旧计划不作为当前角色计划。
- 0.4.2增加生成器版本签名，旧自动计划在下次读取时按新规则更新；人工覆盖计划继续保留。
- 使用线程锁和临时文件原子替换，防止半份JSON；配置和日程草稿分开保存。
- 禁用日程不创建目录、不更新文件、不注入上下文；已有文件保留供重新启用。
- 坏文件不会自动覆盖。接口给出固定错误状态，普通人格回复继续运行。测试或修复时先备份该文件，再移出坏文件并重新生成。
- 存储失败不让日程异常中断原有模型请求。
- 后台任务随插件停用/重载取消并等待结束；配置保存时也会刷新任务。

当前版本没有模型驱动规划、节假日服务、实时天气、情绪推断、自动现实执行及消息分段。这些能力需要独立设计，不能仅靠日程开关获得。
