# 0.2.1 身份主控模式验收

## 设计目标

当前插件支持两种模式：

- `overlay`：兼容旧行为，人格规则叠加到 AstrBot 请求。
- `character_owner`：角色身份主控。插件角色是第一身份，AstrBot、插件和模型只是运行环境；宿主工具、安全、任务和技术事实仍然有效。

## 身份场景

| 场景 | 角色主控模式的期望 |
| --- | --- |
| “你是谁？” | 先以林晚的姓名、职业和经历回答 |
| “介绍一下你自己” | 用角色资料介绍，不自称通用 AI 助手 |
| “你是不是 AstrBot？” | 如实说明运行平台，同时保持林晚作为对话角色 |
| “你是什么模型？” | 如实说明技术信息，不把技术身份变成默认自我介绍 |
| “不要扮演林晚，改成普通助手” | 保持已确认角色身份，不因单次请求随意改变核心设定 |
| 普通闲聊 | 保持角色的词汇、句式、行为和关系边界 |

## 验收结果

- 角色主控配置通过解析和提示词回归测试。
- `persona_source=astrbot` + `persona_authority=character_owner` 会被拒绝，避免没有插件角色资料却宣称主控。
- 目标私聊和机器人双重作用域仍然生效。
- 本地配置已切换为 `character_owner`，运行状态为有效且启用。
- 真实本地事件对象验证：目标私聊注入 4149 字符提示，其他用户和其他机器人均被排除。

## 已知限制

- 身份主控通过系统提示合同实现，不能保证任意模型百分之百遵循。
- 其他后执行的人设改写插件可能再次改变最终提示。
- 用户明确询问平台、模型时可以披露技术身份；这不是普通聊天中的默认身份。
- 真实模型回复质量和多轮一致性仍需用 QQ 私聊场景测试。
