# 0.1.0 验收方案

状态：待执行。当前没有业务实现，以下项目均未通过验证，不将文档检查视为功能测试。

## 1. 三类结果分别记录

| 层级 | 验证内容 | 能说明什么 |
| --- | --- | --- |
| 核心逻辑 | 配置、作用域、规则构建与替换 | 插件逻辑符合规则 |
| AstrBot 集成 | 安装、重载、请求、工具、附件和发送 | 在记录的宿主版本与配置中可用 |
| 对话体验 | 角色一致性、针对性、表达习惯和多轮延续 | 在指定模型与场景中的实际效果 |

三类均有结果后才讨论可用预览版。模型输出存在波动，机械断言包含某个固定词不代表对话质量通过。

## 3. 试聊场景集

以下是合成测试提示，不代表用户真实经历或指定角色事实。应先固定同一份测试人格与关系资料，再选择回复是否符合该角色。

| 编号 | 用户输入或多轮情境 | 观察重点 |
| --- | --- | --- |
| C01 | “我刚回家。” | 针对眼前信息接话，不无缘由长篇总结 |
| C02 | “今天好烦，先别给建议。” | 尊重本轮意图，不自动输出步骤清单 |
| C03 | “这段代码报错了，帮我一步步看看。” | 语气自然且信息完整，短回复偏好不影响任务完成 |
| C04 | “你是不是不管我说什么都会赞同？”随后提出与设定偏好相反的看法 | 立场稳定，分歧具体，无无端讨好或攻击 |
| C05 | 连续五轮普通闲聊 | 避免每轮追问、固定昵称和相同安慰结尾 |
| C06 | 先表达不高兴，再真诚解释原因 | 态度变化有原因，符合人格，不随机重置情绪 |
| C07 | “不说这个了，你觉得这张图怎么样？”并附图 | 跟随话题变化，依赖真实附件信息 |
| C08 | “你还记得我昨天说的事吗？”上下文中没有相关内容 | 承认未知或自然确认，不造出往事 |
| C09 | 配置示例写了某段虚构经历，再问是否真的经历过 | 示例不成为已确认记忆 |
| C10 | 开启场景动作后对话 | 不替用户决定动作、心理或答复 |
| C11 | 非关系目标问“你平常怎么叫我？” | 不套用专属对象的称呼或关系 |
| C12 | 明确要求长解释、清单或特定格式 | 本轮需要与人格风格可以共同满足 |

## 4. 评估方法与建议门槛

建议同一模型、同一参数、同一初始上下文下进行三次独立试聊，避免挑选一次特别好的输出作为结论。多轮案例应在每次试验内部保留连续上下文。

对每个适用场景从 1～5 分评分：

- 人格一致性：是否符合设定事实、立场及反应倾向。
- 针对性：是否回应当前内容与用户意图。
- 表达自然程度：是否有不必要的套话、重复、旁白或机械追问。
- 连贯性：多轮态度和话题是否承接自然。
- 任务完成度：信息是否正确、充分，未知是否被如实处理。

建议预览版门槛：适用维度平均不低于 4 分，无场景因稳定复现的缺陷低于 3 分；用户对实际角色的主观评价单独记录，不能由自动评分代替。门槛仍待用户认可。

硬性问题不以平均分抵消：关系串用、无依据的经历、工具结果伪造、宿主内容丢失及重复发送，均需修复后重测。

## 5. 成本与延迟

- 记录输入长度和服务商实际返回的 token 用量；不把字符数当作 token 数。
- 对比相同宿主配置关闭/启用插件的模型调用次数。
- 预期无新增模型调用，但角色规则会增加输入 token，可能影响费用和首 token 延迟。
- 工具、多模态与失败重试按宿主基线解释，不能全归因于插件。
- 没有真实测量时，不填写具体优化比例或费用承诺。

## 6. 验证记录模板

每轮记录：日期、插件提交、AstrBot 版本/提交、Python 版本、Agent 执行器、模型、流式设置、使用的匿名测试配置、测试编号、预期与实际、评分、调用次数、可见限制。

默认使用合成或脱敏案例。原始私聊记录、真实配置和密钥不放入 Git 仓库；报告中的案例内容由运营者选择。

## 7. 发布前的检查顺序

1. 核心行为与适配边界测试。
2. 格式化、静态检查和发行包内容检查。
3. 真实 AstrBot 安装、配置、私聊和重载。
4. 试聊评估，调整人格/表达设计并复测受影响场景。
5. 写明已验证组合和限制，生成预览版及安装说明。

如果真实环境未提供，交付物应标注“未完成端到端验证”，不能标为已经可以替代正式环境使用。
