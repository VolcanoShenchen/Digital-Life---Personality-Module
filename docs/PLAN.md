# General_purpose_personality_plugin 项目计划

版本：实施记录 v5。首版方案已获用户确认，当前处于内部测试预览阶段。

## 1. 已确认基线

- 全新 AstrBot 插件，不参考旧插件的能力、兼容与数据迁移。
- 项目名称 General_purpose_personality_plugin，内部宿主标识 astrbot_plugin_digital_life_personality。
- 首版单角色，默认由插件统一管理人格和表达，也提供沿用 AstrBot 人格的表达模式。
- 主要目标是 NapCat 经 aiocqhttp 接入的 QQ 私聊。
- 专属关系只适用于指定私聊和指定机器人。
- 状态、长期记忆、多角色、主动联系等后续分别规划。
- 先确认模块方案，再进行该模块的业务实现。本次首版方案已经确认。

- 人格、关系、表达习惯与示例规则的组装。
- UMO、平台、私聊类型与机器人自身账号的联合匹配。
- 完整自有区块替换；先校验结构，损坏、嵌套与交叉标记时保留原请求。
- 保留宿主历史、模型、工具、附件和普通发送流程。
- 有限容量、按来源和机器人隔离的诊断信息，不持久保存聊天副本。
- 管理面板 Schema、元数据、开发工具配置、测试与完整 ZIP 构建器。

具体配置见 [首版设计](DESIGN_V0_1.md)，操作见 [安装说明](INSTALL.md)。

## 4. 固定接口基线

AstrBot v4.29.4，官方提交 61335414433db721b3f7ecc93f90deafe0a59d78；Python 3.12+；内置 Agent。

源码证实 UMO 不包含 self_id，因此按原设计的隔离要求增加 allowed_bot_ids 和 relationship.target_bot_id。安装后的会话名单与机器人名单默认均为空，不会生效。

接口核对不等于真实宿主运行通过。元数据当前精确限定 4.29.4，需根据实际环境测试后再扩大兼容范围。

## 5. 当前模块划分

```text
main.py                  AstrBot 生命周期、请求钩子与状态命令
settings.py              配置解析、校验与不可变结构
personality.py           人格表达、作用域与区块结构处理
runtime.py               请求处理与有限诊断
_conf_schema.json        配置面板
metadata.yaml            宿主标识及版本范围
scripts/build_plugin.py  显式清单打包与验证
tests/                   核心、适配、结构回归和安装包测试
docs/                    设计、安装、验收与验证记录
```

首版没有专用角色数据库、记忆库或单独 Web 服务。
